The user wants an overall picture: what the records hold, what is strong, what to do next. Mostly inline work by you; one ranking pass if rankings are stale.

1. **Inventory.** Count questions by status and round; list jobs still running in this session; note the date of the last ranking comment and whether questions changed since.
2. **Rank if stale.** If no ranking covers the current versions, run `steps/judge.md` (ask first if it would start more than a couple of jobs).
3. **Think through** (in `<work>/review.md`, not recorded):
   - Top questions by averaged rank, each with its one-line plain statement and First experiment.
   - Experiment cards waiting for the researcher, and results that changed a belief since the last review.
   - Single-judge picks and largest-spread questions (F32), as candidates for the user's own judgment.
   - Composition mix of the portfolio (A+B / A−B / A+1 / other) and whether any question goes beyond composition (F22, F23).
   - Recurring weaknesses from Check notes, by checklist item (F24, F25, F29).
   - Questions where development stalled (kept twice with the same obstacle, or under the stall rule) and questions whose first experiment is ready to run now.
   - The notebook: beliefs with weak evidence that much depends on, open threads older than two weeks, unresolved disagreements.
   - Time left to the deadline in the notebook's Constraints against the compute and steps the top questions need.
   - Suggested next actions, each a concrete /r42 request (e.g. "deep-dive q007, 2 rounds", "propose with hints 5, 9 and 13").
4. **Reply** with the direct answer to what the user asked: where things stand in one or two sentences, the top one to three questions (one line each), and the one next step you recommend. Post one short comment on the notebook with the same content as the reply (top questions with issue links, the recommended next step) and link it.
